## Implemented

- Shared types distinguish local IDs from real cloud project IDs and define local metadata plus bounded, revisioned operation contracts.
- Self-scoped project list/summary/slug/create endpoints derive the caller from verified `ctx.auth`. Their historical `principalId` claim is optional and checked if present. Project update/artifacts/status/archive/restore/delete handlers also check their caller claim and use the derived principal for access and ownership.
- Migration 4 adds `local_projects` and `project_operations` to Electron's existing catalog. It backfills historical identities without changing workspace references or touching source folders. Post-migration legacy workspace imports receive local entries on catalog listing.
- Local metadata supports personal name/hide choices and optional shared observation. Shared projection never becomes authorization or replaces an existing association with another project.
- Creation identity and intent commit transactionally. Original requests are immutable; operation transitions use revision checks, monotonic stages, terminal states, bounded errors and immutable appended resource evidence.
- Typed workspace project IPC and preload methods expose catalog/journal operations. Catalog snapshots include all local project entries; project metadata changes broadcast without invalidating unrelated workspace resolutions.
- Main-owned folder workflows reserve paths/identities before effects, preserve ownership on retries, reconcile a committed binding after a lost receipt, reject replaced sources, and make no cloud calls. Existing create/import UI uses these workflows. Unfinished unbound attachments are found by exact source through a narrow journal lookup and retain their original request even if a later form supplies another name.
- Daemon launch wiring supplies Electron's concrete catalog path. Read-only import retries absence and does not overwrite existing bindings. A live bridge sends verified bindings, validates receipts, retries failures and refreshes after daemon restart; omission never deletes headless session state.
- Daemon registration validates input, prevents cross-project/stale binding claims, updates ordinary workbench revisions transactionally, permits initial qualification of older partial registrations, and refuses retained session relocation.
- Renderer hooks use an optional genuine cloud client boundary. Missing configuration renders ordinary children, unavailable cloud handles fail on invocation, and retained pages preserve subscriptions through the genuine query facade.
- Device presentation persists locally after checking the installation key, with checked historical presentation migration and bounded atomic updates. Shell/onboarding/navigation entry uses local readiness; fresh launch does not enroll a cloud principal. Cloud profile failure clears cloud authority while preserving the local shell. Explicit cloud connection entry points are available in settings, organization Store and project join.
- Project routes resolve durable local identity separately from genuine optional shared documents, canonicalize known shared/slug links while preserving intents, reject mismatched cached projections and present ambiguous slug choices. Unknown local keys never enter cloud discovery; the normalized legacy route endpoint authenticates and checks access.
- Workspace providers/hosts and headless runtime policy no longer require a cloud principal. Workbench/title/changes navigation uses local identity; association updates retain the same runtime/session/PTY snapshot. Switch prefetch takes a separate genuine optional cloud ID, and local Changes remains available without a shared document.
- Local checkpoint-ref cleanup is independent of cloud activity; the latter requires genuine association plus active collaboration membership. Shared retry/concurrent-commit reconciliation remains pending.
- Sidebar, Search and tour discovery read durable local projects without mounting a cloud project list. Genuine optional shared documents only enrich existing associations. Hidden/unbound rows retain local ordering; moving visible rows preserves hidden entries. Rename/hide and default project settings affect this device; shared management is explicit and shared deletion preserves local workspace/runtime ownership.
- Creation requests flush to the existing desktop persistence store before native IPC and survive renderer restart. Optional scaffold/GitHub effects record progress before execution; uncertain effects are not automatically repeated. Opening an already-created project archives its unresolved optional receipt before clearing the active request. Corrupt intent and a full bounded archive fail closed. Main-owned optional-effect reconciliation/recovery remains pending.
- Create/open/resume replies await a post-commit catalog broadcast and verify the returned project/workspace. The barrier waits out an in-flight older read and performs a fresh read; navigation cannot outrun the discovery snapshot. Unavailable confirmation retains the saved request for retry.
- Local name/hide replies also await and verify their committed snapshot before controls become available, preventing quick hide/show from repeating a stale value. Only the visible destination project/workspace consumes create/import tile intents. A verified non-Git folder uses its concrete catalog lane; unresolved Git/stale catalog scopes still wait. Ordinary create/import reuses an existing assistant tile, including after renderer reload.
- Assistant binding refreshes the authoritative local T3 snapshot after project creation, so a pushed read-model delay cannot produce a false failure. The workspace lock serializes binding while allowing a cancelled effect's replacement to reconcile the same project; obsolete completions do not clear the replacement's status.
- Original-folder repair journals the old/new canonical roots, original physical directory identity, exact workspace ID and expected revision before effects. It requires an exact daemon acknowledgment and stops workspace Dev Server/workbench/terminal ownership before committing. Retries retain intent/IDs and reconcile a committed revision after response loss. Copies/replacements and retained session relocation are rejected; a different directory occupying the former path is preserved. Root repair leaves independent worktrees unchanged and downgrades moved managed folders outside their root to attached. Legacy moves without physical identity and nested/unbound repairs remain separate work.
- Missing managed bindings retain their IDs and lanes during other creations. Fresh destination allocation skips absent catalog and unfinished-operation reservations as well as existing folders. Both folder-location UI entry points use the high-level journal; local settings remain accessible with a broken binding. Recovery panels on launch/settings/missing-folder surfaces retry saved create/attach/repair receipts. Scoped journal filtering precedes its limit.
- Startup inspects at most 128 recovery rows and starts at most 32 local create/attach retries, checking a 15-second elapsed limit between operations. It does not automatically retry failed attempts, explicit repair/removal or optional network effects. This is not a hard per-operation deadline.
- Completed consecutive repair revisions alone authorize private workbench/chat relocation. Workbench tiles, active selection and layout reset key survive; layout persistence advances its binding revision before presentation resumes, and stale outgoing layout writes are rejected. Unavailable confirmation preserves old state for retry. The assistant lock stops idle provider sessions, blocks running chats, rebases the same native project and checks its committed snapshot. Exact old-root drafts/history update without changing native chat IDs or independent worktree associations. Renderer generic journal writes cannot forge local lifecycle completion evidence.
