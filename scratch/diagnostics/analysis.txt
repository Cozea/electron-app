It turns out `@base-ui/react` has a nearly 1-to-1 feature parity with `@radix-ui/react`, meaning we can systematically replace almost all the bulky Radix primitives with headless Base UI primitives!

Here are the highest-impact components in your app that would benefit the most from being migrated to `@base-ui/react`:

### 1. High-Frequency Overlays (Dropdowns, Menus, Popovers, Selects)
* **`dropdown-menu.tsx`**, **`select.tsx`**, **`popover.tsx`**
* *Why:* Radix handles overlays by aggressively injecting them into `document.body` via Portals and computing massive `DOMRect` calculations on every scroll/resize, which can cause jank (especially inside our new Electron `ProjectShellLayout`). Base UI uses a completely modern approach powered by the native Floating UI `Positioner` system, which is incredibly lightweight and handles nested menus flawlessly without blocking the main thread.

### 2. High-Interactivity Forms (Switches, Checkboxes, Tabs)
* **`switch.tsx`**, **`checkbox.tsx`**, **`tabs.tsx`**, **`radio-group.tsx`**
* *Why:* Base UI handles focus management and screen-reader accessibility completely headless. Instead of Radix forcing you to use their specific `div` wrappers that break CSS Grid styling, Base UI uses a strict `render` prop and `asChild` delegation that is much cleaner and easier to style with Tailwind.

### 3. Complex Layout Containers (Dialog, Sheet, Sidebar)
* **`dialog.tsx`**, **`sheet.tsx`**, **`alert-dialog.tsx`**
* *Why:* These components manage "Focus Traps" (preventing the user from tabbing outside the modal) and "Scroll Locks" (preventing the background from scrolling). Radix's implementation has known bugs where it sometimes fails to release the scroll lock when a modal unmounts unexpectedly. Base UI has a much safer, more modern focus-trap algorithm.

### 4. Interactive Data (Avatar, Progress, Collapsible)
* **`avatar.tsx`**, **`progress.tsx`**, **`collapsible.tsx`**
* *Why:* Moving these ensures that your entire design system is unified under a single accessible headless library, rather than shipping *both* Radix and Base UI to your users (which dramatically bloats your bundle size).
